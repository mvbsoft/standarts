# Стандарти

> Версія 1.0.0-draft · Українська · [English](README.md)

Один стандарт організації програмних проєктів незалежно від мови: середовища, Docker, ворота
якості, поставка й розгортання, бекапи, документація й налаштування для ШІ-агентів (поки єдиний
адаптер — Claude Code). З кожним
проєктом, побудованим за ним, працюють однаково: ті самі команди `make` його налаштовують,
запускають для розробки, перевіряють, поставляють, розгортають і відкочують, а його README
починається з тієї самої таблиці про те, що й коли запускати. Стандарт застосовує ШІ-агент: він
створює новий проєкт або проводить аудит наявного, питає власника про те, що може вирішити лише
власник, планує зміни й виконує їх після схвалення.

> **Чернетка.** Релізу ще немає. До `v1.0.0` промпт нижче — лише для перевірки:
> склонуйте `main` самі й у промпті замість рядків `STANDARD_REPO`, `STANDARD_REF` і завантаження
> дайте `STANDARD_DIR=<ця папка>`.

**Вперше тут? Почніть зі [стандарту на одній сторінці](GUIDE.uk.md):** карта того, що робити в
кожній ситуації, яка команда `make` це робить і де деталі.

## Як застосувати в проєкті

Що потрібно на машині: Linux або WSL 2 у Windows з проєктом усередині WSL (не на диску Windows),
хостові інструменти й версії, які називає
[PRN-01](standard/01-principles.uk.md), і агент (поки підтримується лише Claude Code). Більше нічого
не встановлюється: усі мовні інструменти працюють у dev-контейнері проєкту.

Відкрийте агента в кореневій теці проєкту і вставте:

```text
Apply the project standard to this project.
STANDARD_REPO=mvbsoft/standarts
STANDARD_REF=v1.0.0
Fetch that release with
  git clone --depth 1 --branch "$STANDARD_REF" "https://github.com/$STANDARD_REPO.git" "$HOME/.cache/standards/$STANDARD_REPO/$STANDARD_REF"
(skip it if the folder exists), then read and follow $HOME/.cache/standards/$STANDARD_REPO/$STANDARD_REF/prompt/start.md.
```

Промпт англійською, бо його виконує агент; відповідати вам агент буде мовою, якою ви пишете.
Режим агент обирає сам; для проєкту, що вже має реєстр, питає, чи оновити, чи налаштувати заново:

| Проєкт | Режим | Результат |
|---|---|---|
| ще не має реєстру | adopt | звіт аудиту в `~/audits/<репо>/<дата>/`, план у беклозі проєкту, зміни після схвалення |
| налаштований старішим релізом | update | лише правила й шаблони, що змінилися між двома релізами, і питання, які додав новий реліз; потім агент пропонує по одній переглянути ваші попередні відповіді |
| уже налаштований, і ви хочете ще раз пройти весь свій вибір (stage, мутаційне тестування, бекапи) | set up again | агент ставить усі питання з початку, показує ваші поточні відповіді й приводить проєкт до нових |
| ще не існує (порожня тека) | new | каркас нового проєкту, що відповідає стандарту, з доведеною працездатністю, закомічений після схвалення |

Звіт лежить поза будь-яким репо, і після переведення його можна видалити. Якщо щось у ньому може
покращити стандарт, звіт містить знеособлений `proposals.md`; за бажання надішліть його сюди як issue.
Чого стандарт ще не вирішує і що ви можете зробити самі:
[відомі обмеження](standard/README.uk.md#відомі-обмеження).

репо нічого не копіюється, крім шаблонів.

## Версії

Релізи — git-теги `vMAJOR.MINOR.PATCH` у `main`. Мажорний реліз означає, що проєктам доведеться
щось змінити (нове правило чи частина, від якої проєкти не можуть відмовитися, — це мажорний реліз), мінорний додає правила чи шаблони, які
проєкти можуть узяти, патч лише уточнює текст. Реєстр кожного проєкту називає реліз, за яким він
живе. Як розвивається сам стандарт: [CONTRIBUTING](CONTRIBUTING.uk.md). Ліцензія: [MIT](LICENSE).
